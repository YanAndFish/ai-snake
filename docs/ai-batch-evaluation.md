# 多结果与提前请求实验

本轮共运行 32 局真实 Decisions API 游戏。多结果提前请求模式未达到预定标准，当前游戏使用单方向模式。

## 多结果表示什么

每个请求包含最多九个独立问题，分别描述等待期间直行零到八步后的可观察局面。模型为每个问题同时选择方向或 KEEP，以及持续一到六步。所有非反向方向和持续步数都可以选择，包括会碰撞的操作。

响应到达后只采用与移动编号、蛇身、朝向、食物和速度匹配的一个回答。其余回答不会拼成路线。方向和持续步数全部来自 AI，本地只做局面预测、格式校验和执行。

[Decisions 官方指南](https://developers.openai.com/api/docs/guides/decisions#ask-multiple-questions)说明，同一请求适合包含独立问题，依赖前一答案的决策应分开请求。本实验将方向和持续步数编码在同一个选项中，各问题不依赖其他回答。

提前请求版本在执行当前操作时预测该操作的终点，并从这个终点请求下一批。预测只执行 AI 已选定的方向。若已知食物会在当前操作中被吃到，等新食物实际出现后才预测其后的局面。

下一批早到时等待当前操作结束，到达起点后核对局面再执行。晚到时使用覆盖范围内与实际局面匹配的回答；超过范围时丢弃并重新请求。等待期间按当前方向移动，每局最多一个在途请求。

## 如何权衡得分与存活

每局综合分 = 游戏得分 + 存活秒数 ÷ 2。吃一个食物增加十分，等价于二十秒存活加分。综合分仅用于实验比较，游戏中显示的分数不变。

开发阶段要求总得分和综合分均提高。独立验证要求平均游戏得分提高、平均综合分至少增加五分。存活时间与提前死亡次数单独报告，不设存活不能下降的硬门槛。

## 固定实验条件

- 基线提交：`7eb7e83e6db7ad053211355c69cbbb0af1fabd76`。模型为 `gpt-6-luna`，标准难度、19×19 棋盘、60 Hz。
- 两组开发种子分别为 1201–1203 和 1211–1213，每局 30 秒。
- 独立验证使用 1301–1310，每局 60 秒。候选源码在开始前冻结。
- 同种子配对，每轮同时运行两局，轮换创建顺序。双方死亡后都等到固定窗口结束。
- 首个响应前死亡、503、无效或过期回答全部计入，没有预热请求或重开筛选。

## 失败原因与限制

四局在第一个有效操作前结束。其中种子 1305、1306、1309 的响应在约 1.53–1.64 秒到达，此时蛇已完成九次移动，超出本次批量问题覆盖的零到八步范围，因此响应被丢弃。种子 1307 在首个响应到达前碰撞。

这四局的首个请求各有九个问题，请求正文约 32 KB。三个过期响应不能视为 API 没有返回，也不能据此断言模型选择错误。当前批量覆盖范围与开局延迟不匹配，是该样机的明确限制。

种子 1303 中，模型选择连续向下六步，再向下三步，最终到达底部边缘。下一次响应未到达，蛇按当前方向撞墙。种子 1310 获得 70 分，但约 43.2 秒结束。提前请求和更多步数没有消除响应延迟风险。

本轮只测试这两个冻结版本，没有在独立验证种子上调整覆盖范围、开局策略或权重后重新宣称通过。样机保留供复现，不接入正式游戏。

## 检查与复现

样机的 216 个单元测试通过，包括提前到达、晚到、暂停取消、危险持续步数、KEEP、食物变化和执行来源。覆盖率门槛、TypeScript、热路径检查、构建和浏览器自检通过。语句覆盖率为 93.03%，分支覆盖率为 86.83%。请求并发以生产解析器读完响应体为止统计，额外调试副本的读取时间不计入网络请求。

每一局检查源码稳定性、真实 60 Hz 时钟、请求清理、运行时不变量和实际移动来源。将选中问题、API 原始答案、方向及持续步数与执行记录逐项核对。没有发现无 AI 输入的自动转向、KEEP 改变方向或在错误起点执行操作。

完整记录为 gzip JSON，包含 `reports`、`variantSources`、`variantForStage`、`plan` 和浏览器自检结果。凭据已隐藏，棋盘快照省略 RNG。源码快照和报告中的 SHA256 用于核对实际待测版本。

多结果记录用 `batchTrace.selectedMoveCount` 表示实际选中的起点，过期以 `ExpiredBatchError` 判断。`expectedStartMove` 是最早预测起点，`expiredOnArrival` 仅比较该起点，不能据此判断整个批量响应是否过期。

复现时从基线提交建立隔离目录，用 `git apply --unidiff-zero` 应用对应补丁，安装相同锁文件的依赖。从 `reports[阶段].results[].scenario` 提取场景数组，只替换源码目录。两种模式都使用提前请求版目录中的评估脚本，以记录完整回答和实际执行来源。

```sh
node /path/to/batch-v2/scripts/evaluate-live.mjs --env-file /path/to/.env.local --scenarios /tmp/scenarios.json --concurrency 2 --output /tmp/result.json
```

结果只覆盖标准难度。网络、服务端响应和模型选择存在波动，复测分数可能不同。
