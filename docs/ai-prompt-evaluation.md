# 当前方向控制的提示词实验

在 10 个独立种子的配对测试中，每局计分窗口为 60 秒。候选的平均得分为 12，基线为 6。平均存活为 45.1 秒和 20.6 秒，活满窗口分别为 7/10 和 2/10。采用候选 `lean`。

这些是本次有限样本的结果，不表示所有棋盘都改善，也不作统计显著性结论。首个响应前死亡的样本全部计入。

## 实验条件

- 模型固定为 `gpt-6-luna`，浏览器原生 fetch 请求 Decisions API。
- 标准难度，60 Hz 游戏时钟，每 10 tick 移动一格。每局只有一次生命，死亡后得分冻结到计分窗口结束。
- 同种子的两个版本在同轮运行，总浏览器并发为 2，轮换创建顺序。
- 开发种子为 301、302、303，每局 30 秒。独立验证为 401–405 和 501–505，每局 60 秒。
- 两组独立验证使用同一个冻结版本。第一组总得分持平后，再用第二组独立种子复测；两组全部合并统计。
- 基线提交为 `2fc101dd01b9b4881d47da1783793ccb4a8c19f0`。所有实验变体的生产代码差异仅在 `src/ai/prompt.ts` 和 `src/ai/client.ts`。

选型标准为总得分提高，同时总存活时长和满窗口存活局数不下降。开发数据不进入独立验证汇总。记录了 59 局真实游戏，其中独立验证 20 局，其余用于问题观察和提示词比较。

## 观察到的问题

1. **首个响应来不及。** 最初三局基线中，两局约 1.7 秒死亡，尚无响应完成。提示词无法保证网络请求赶在碰撞之前完成。
2. **能活，但不吃。** 最初第三局活满 30 秒、完成 51 次决策，得分为零。成功响应中位耗时约 436 毫秒，蛇反复绕过同一食物。
3. **转向后没有足够等待时间。** `compact` 的种子 301 选择向左后，只能直行约 500 毫秒，而近期响应 P90 为 600 毫秒。下一次响应没赶上，蛇撞墙。
4. **快照中的进食机会已经错过。** 同一例子中，请求时食物就在左侧一格，但约 437 毫秒后，蛇已向上移动两格。模型要结合响应时间判断，而不能只看请求时的距离。

## 提示词和信息

正文保存完整的当前蛇身、食物、速度、响应延迟和食物停滞时间。方向选项分别提供：

- `safe_for`：执行该方向后，从首次移动到保持直行发生碰撞的时间。
- `margin`：`safe_for` 减去近期响应 P90，用于观察下一次响应是否可能来不及。没有样本时按两次移动估计，并注明延迟未知。
- `food_on_straight`：沿该方向保持直行时，第几步吃到已知食物。
- `food_distance`、`space`、`tail`：首次移动后的食物距离、可达空格数和尾部连通情况。

选项先展示预计响应中位时间的结果，再展示其他时间场景。方向本身按固定顺序排列。提示词要求在时间余量足够时争取得分，避免只追求更多空地。

信息只用于模型判断。所有非反向选项均可选择，危险选项照常提供。游戏的移动速度、请求调度和碰撞执行代码没有修改。尚未出现的食物和 RNG 不进入提示词。

[Decisions 官方指南](https://developers.openai.com/api/docs/guides/decisions)用于核对 `input`、问题说明和选项描述的用法。信息放在正文或选项中的效果由实际对照测试判断。

## 开发阶段比较

| 版本 | 变化 | 观察结果 |
|---|---|---|
| compact | 明确直线进食信息，减少重复说明 | 总分 20 对 0，但存活总时长 26.4 秒对 48.2 秒，未采用 |
| margin | 增加毫秒余量和到达时点说明 | 得分均为零，信息过长，未采用 |
| lean | 精简正文和方向指标 | 同期得分持平，存活略有改善，进入独立验证 |
| evidence | 相同测量数据统一放正文，选项只说明动作 | 总分 10 对 lean 的 20，未采用 |
| arrival | 有延迟样本时只展开响应到达后的结果 | 总分 0 对 lean 的 10，未采用 |
| examples | 增加与实际棋盘无关的指标权衡例子 | 总分 0 对 lean 的 10，未采用 |

不同轮次的网络响应有波动，不能把开发阶段的非同期数据直接当作配对结果。实际请求内容和逐局耗时保存在原始记录中。

`arrival` 在种子 301 和 303 各收到一次 API 拒绝回答，记录中归为解析错误。这两局照常计入开发结果。独立验证没有 HTTP、网络或解析错误。

第一组的总分均为 40，不能单独据此宣称得分提高。第二组为 20 对 80。候选的种子 402 得分和存活略差，种子 505 在首个响应完成前死亡；这些结果都保留在汇总中。结果只覆盖标准难度，本次没有验证其他难度。

## 数据与复现

- [汇总和逐局指标](ai-prompt-results.json)
- [完整请求、执行记录和实验变体源码](ai-prompt-traces.json.gz)

压缩记录为 gzip JSON，包含 9 个阶段的原始报告、各变体修改的源码，以及独立验证计划。汇总中记录压缩文件的 SHA256。所有记录已隐藏 Key，棋盘观察省略 RNG。

`dispatchState`、`responseState` 和 `executions` 分别记录发出请求、完成解析和实际移动时的局面。全部有执行记录的样本中，未发现无 AI 输入的自动转向，也未发现实际输入与模型返回不一致。

使用 `scripts/evaluate-live.mjs --scenarios` 复现。将压缩记录中对应报告的 `results[].scenario` 提取成数组，替换其中的源码根目录：基线使用上述提交的独立检出，候选使用当前源码。两份源码安装相同锁文件的依赖。保持种子、难度、时长、轮次和并发为 2，然后运行：

```sh
npm run eval:live -- --env-file /path/to/.env.local --scenarios /tmp/scenarios.json --concurrency 2 --output /tmp/result.json
```

复现会产生真实 API 请求。先检查 `sourceStable`、`passed`、真实解析数量和执行来源，再比较同种子的得分与存活。随机响应和网络延迟会使结果变化。
